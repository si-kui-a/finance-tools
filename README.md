# 財務工具（快速健檢 ＋ 帳本 ＋ 成本試算 ＋ 工時反推）

## 核心原則

- 同一份資料只輸入一次，收入、帳戶、成本試算、工時與首頁分配共用同一來源。
- 優先處理生活、固定支出與財務風險；其他成本目標由使用者自行選擇。
- 計算公式透明、可測試、可匯出，不依賴 AI、後端或外部服務。
- 預設操作簡單，進階設定折疊；已知數值由系統推導，不要求重複輸入。
- 保留舊資料相容性，以低維護成本維持長期正確性。
- 全站使用一致的文字、符號、元件與視覺層級。

純前端靜態網頁，無後端、無第三方套件、無 AI 依賴。所有運算在瀏覽器本機執行，不會把資料送到任何伺服器。

## 快速開始

1. 直接用瀏覽器打開 `index.html`，或部署到 GitHub Pages（Settings → Pages → 選擇分支 → 儲存即可，免設定）。
2. 第一次使用先開「財務健檢」：只需目前年齡、稅後收入、必要支出、其他支出、可動用資產，以及第一個目標的金額／期限，不用先匯入帳本即可得到每月結餘、儲蓄率、緊急預備金、通膨後目標與三種壓力情境。
3. 「帳本」分頁：記錄支出／收入／願望清單，支援台幣以外的幣別（記帳時當場輸入匯率），
   即時看到分類小計、可動用資金、非必要支出、可報銷總額、消費/薪資趨勢圖。
4. 「成本試算」分頁：切換情境（買房／買地自建／學貸／旅費／喪葬費／養老金／FIRE 退休），
   編輯項目金額，即時看到總額與通膨後金額，可展開「顯示算式」核對計算過程；
   每個情境下方會自動顯示「約需工作多久／幾歲可達成」的提示（呼叫工時反推引擎的正式計算）；
   學貸情境可標記任一期為「休學」，該期金額自動歸零；
   FIRE 情境可切換稅前/稅後薪資基準，也可反過來用「薪資成長率」推算幾歲能退休。
5. 「工時反推」分頁：只輸入月總工資與月工時，即自動回算時薪、勞保、健保與估計實領，再換算目標金額需要工作的時數／班次／週數／月數。
6. 帳本頁的「個人參數設定」：設定勞健保費率、投保薪資、每月可存金額、目前年齡（會影響全站的自動提示與 FIRE／工時反推計算）。
7. 帳戶管理可自訂名稱、性質與起始餘額；每筆收入及支出指定帳戶後，系統自動分帳計算目前餘額。帳戶間搬款請用「帳戶轉帳」，不會誤算成收入或支出。
8. 「每月固定出入帳」可同時建立多個正職、兼職、接案及固定支出；每項收入獨立決定是否扣勞健保，並設定發薪／扣款日與帳戶。到期後自動建立當月帳目，同月不重複。
9. 首頁「本月資金分配」會先安排基本生活、固定支出與緊急預備金，再按期限安排使用者勾選的成本目標。每層可指定帳戶；未勾選的成本試算不顯示、不參與分配。
10. 首頁會優先沿用多份工作的稅後收入與流動性帳戶餘額；只有尚未建立這些資料時才要求手動輸入。自動分配是本機建議，不會操作真實銀行帳戶。
11. 工時反推可選擇既有的固定收入來源，自動沿用該工作的工資、工時、投保薪資與勞健保設定；選擇「自訂收入」時才需另外輸入。
12. 固定儲蓄以帳戶間轉帳記錄，不列為支出；可設定每月金額、轉存日、轉出帳戶與儲蓄帳戶。
13. 首頁自動顯示每月應儲蓄、每日可用生活費、本月實際儲蓄率、健康狀態、問題點與達成率。每次新增或刪除帳目後立即重算。
14. 帳本會依分類計算累計花費、跨月平均、占全部支出比例與月預算上限。平均期間包含第一筆與最後一筆支出之間的空白月份，避免只挑有消費的月份而高估或低估。

## 關閉分頁後，資料存在哪裡

- 匯入的原始 JSON 檔不會被移動、複製或改寫，仍留在使用者原先選取的位置；瀏覽器基於隱私不會把完整來源路徑提供給本工具。
- 匯入後的完整工作資料會立即保存到「目前 Edge 設定檔的本機站點資料」：最新版本使用 `localStorage`，滾動版本使用名為 `finance-tools-local` 的 IndexedDB。
- 每次新增、刪除或修改資料都會更新最新版本；IndexedDB 最多保留最近 20 個滾動版本，可用頁尾的「回復上一版本」。
- 關閉分頁或重新啟動瀏覽器後，工具會自動載入最近一次保存的工作區。
- 這些瀏覽器資料不會同步到雲端，也不是一般檔案總管中可直接管理的 JSON。清除 Edge 站點資料、換瀏覽器設定檔或重灌瀏覽器仍可能移除它，因此應定期使用「完整工作區 JSON」備份。
- JSON 匯出會進入 Edge 設定的下載位置。基於瀏覽器安全限制，本工具不能在未經使用者授權下強制寫入 `C:\Projects` 或其他任意 Windows 資料夾。
- 可在首頁「保存與工作區檔案綁定」選擇或建立 JSON；修改後會先保存到 Edge 本機，約 1 秒後自動同步至該檔案。檔案控制權由 Edge 管理，重新開啟後若授權失效，可按「立即同步」重新授權。
- 網頁右下角會常駐顯示最後成功保存日期、時間及目前是否綁定檔案。

### 儲蓄健康度規則

這是本工具的個人規劃規則，不是政府或金融機構的官方評等：負儲蓄為「收支失衡」、低於 10% 為「偏低」、10% 至未滿 20% 為「待改善」、20% 至 40% 為「健康」、高於 40% 為「充足」。每月應儲蓄至少採稅後收入的 20%，若固定儲蓄或緊急預備金月需求更高，則採較高者。
7. 頁面下方「匯出」把目前資料存成帶時間戳記的 JSON 檔案，請自行搬進**私密**倉庫做版本控制（`git add` + `git commit`）。
8. 下次使用時用「匯入」讀回上次匯出的 JSON 檔案即可接續編輯。只匯入自己產生或確認可信的檔案。

## 快速健檢的計算方式

- 核心採「今日幣值」思考，另外用複利顯示目標日期的名目金額：`今日金額 × (1 + 年通膨率)^(月份/12)`。
- 實質報酬率：`(1 + 名目報酬率) ÷ (1 + 通膨率) - 1`。
- 預設通膨取自 `shared/reference-data.js` 的官方資料快照，畫面會顯示來源與資料日期；離線時仍能使用，並可手動覆寫。
- 固定顯示有利、基準及壓力三情境；壓力情境包含收入下降 20%、較高通膨與零投資報酬。
- 財務結果是規劃情境，不是收益保證，也不構成投資、稅務、保險、法律或貸款建議。

## 資料放哪裡

- **這個倉庫（公開）**：只放工具程式碼與範例假資料（`sample-data/`），可以公開，不含任何真實數字。
- **另一個私密倉庫**：放你實際匯出的 `ledger.json`、`config.json`、`estimator_scenarios.json`、
  `wage_reverse_scenario.json`，每次更新都是一次 commit，形成資料的版本歷史。

## 防止真實資料誤入公開倉庫（重要，只需設定一次）

Clone 這個倉庫後執行：
```
git config core.hooksPath hooks
```
之後每次 `git commit` 前會自動掃描，偵測到疑似真實財務資料的檔案會直接擋下。
另外 `.github/workflows/no-real-data.yml` 會在每次 push 後於 GitHub 上再做一次掃描，
作為第二層防護（即使本機防護被略過也會被攔截）。

## 幣別與匯率

不使用共用匯率表，每筆帳目／每個情境自己帶「幣別」＋「當下匯率」，記帳當下手動輸入，
避免因為忘記更新共用設定而算錯。表單會記住你這次瀏覽器 session 裡同幣別最後輸入過的匯率，
方便重複輸入，但不會持久化存檔。

## 勞健保試算

不內建政府的投保薪資分級表（會過期、需要持續維護），改成你自己在「個人參數設定」填入
投保薪資與費率，公式透明固定（`money.js` 的 `grossToNet`/`netToGross`，互為反函式）。
費率預設值僅為示意，請至勞保局/健保署官網核對最新數字後自行修改。

## 已知限制（誠實列出，非隱藏風險）

- GitHub Pages 網址一定是公開的，安全性依賴「私密倉庫真的只放資料、不放這個工具程式碼」。
- 未按「匯出」就關閉分頁會遺失當次輸入（離開頁面時瀏覽器會跳出警告提醒）。
- 手機瀏覽器可以開啟使用，但匯入/匯出檔案與 git 操作仍建議在電腦上進行。
- 工時反推引擎目前只驗證了「週末班」這條鏈，若原表還有「全週班時數」等更深層欄位，需要你自行核對。
- 成本試算中的舊情境仍保留原表的固定通膨倍數以便重現舊表；新的快速健檢已改用具有來源日期的年通膨率。兩者用途不同，不應混用。
- 官方通膨快照不會在離線網頁中自行改寫；資料過期時請更新 `shared/reference-data.js` 或直接在快速健檢覆寫年通膨率。

## 反推公式的核對狀態

- 買房／買地自建／旅費／喪葬費四個情境的加總公式已用原表數字交叉核對，`通膨後總額 = 總額 × 通膨倍數`
  （一次性直接相乘，非複利），可直接信任。
- 學貸情境的「學期總結」公式已核對，但「學年總結」跨學期加總方式原表有合併儲存格疑慮，已在
  `shared/config.js` 的 `SCENARIO_STUDENT_LOAN` 註解中標明，可自行滾動修正。
- **FIRE／財務獨立退休試算**：固定退休年齡模式保留原表公式；反推退休年齡已改為月度現金流，薪資先換成淨薪、扣除生活費、按月累積報酬，並同時納入退休資產、買房、留學與緊急預備金。結果仍取決於使用者假設，不是保證。
- **養老金試算**：原表用了較複雜的複利成長試算，從錯位表格無法完全還原，此處改用透明可核對的標準
  公式（每月生活費 × 12 × 退休後年數），已在算式面板中完整標示計算過程。
- **工時反推計算機**：用「期望收益 910,626」與「學貸還款 155,893」兩組真實數字交叉驗證，
  換算鏈與「上一步無條件進位後才往下除」的精度規則皆已確認吻合原表。

## 開發者測試工具

不需安裝第三方測試套件；使用 Node.js 內建測試器：

```powershell
npm test
npm run check
```

`npm run check`會依序執行所有JavaScript語法檢查與測試。目前測試涵蓋官方資料快照、複利通膨、實質報酬、快速健檢三情境、緊急金不重複計入目標本金、無條件進位、無效輸入、帳本重複ID、日期、外幣匯率、FIRE零報酬及目標單調性。

GitHub Actions會同時執行隱私資料掃描及測試。隱私掃描由`scripts/check-no-real-data.sh`統一提供，本機hook和CI不再各自維護不同規則。
