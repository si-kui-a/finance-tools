# 財務工具（帳本 ＋ 成本試算 ＋ 工時反推）

純前端靜態網頁，無後端、無第三方套件、無 AI 依賴。所有運算在瀏覽器本機執行，不會把資料送到任何伺服器。

## 快速開始

1. 直接用瀏覽器打開 `index.html`，或部署到 GitHub Pages（Settings → Pages → 選擇分支 → 儲存即可，免設定）。
2. 「帳本」分頁：記錄支出／收入／願望清單，支援台幣以外的幣別（記帳時當場輸入匯率），
   即時看到分類小計、可動用資金、非必要支出、可報銷總額、消費/薪資趨勢圖。
3. 「成本試算」分頁：切換情境（買房／買地自建／學貸／旅費／喪葬費／養老金／FIRE 退休），
   編輯項目金額，即時看到總額與通膨後金額，可展開「顯示算式」核對計算過程；
   每個情境下方會自動顯示「約需工作多久／幾歲可達成」的提示（呼叫工時反推引擎的正式計算）；
   學貸情境可標記任一期為「休學」，該期金額自動歸零；
   FIRE 情境可切換稅前/稅後薪資基準，也可反過來用「薪資成長率」推算幾歲能退休。
4. 「工時反推」分頁：設定目標金額、時薪、是否比照一般受雇試算勞健保，換算成需要工作的時數／班次／週數／月數。
5. 帳本頁最上方「⚙ 個人參數設定」：設定勞健保費率、投保薪資、每月可存金額、目前年齡（會影響全站的自動提示與 FIRE/工時反推計算）。
6. 頁面下方「匯出」把目前資料存成帶時間戳記的 JSON 檔案，請自行搬進**私密**倉庫做版本控制（`git add` + `git commit`）。
7. 下次使用時用「匯入」讀回上次匯出的 JSON 檔案即可接續編輯。

## 資料放哪裡

- **這個倉庫（公開）**：只放工具程式碼與範例假資料（`sample-data/`），可以公開，不含任何真實數字。
- **另一個私密倉庫**：放你實際匯出的 `ledger.json`、`config.json`、`estimator_scenarios.json`、
  `wage_reverse_scenario.json`，每次更新都是一次 commit，形成資料的版本歷史。

## 防止真實資料誤入公開倉庫（重要，只需設定一次）

Clone 這個倉庫後執行：
```
git config core.hooksPath hooks
```
之後每次 `git commit` 前會自動掃描，偵測到疑似真實財務資料的檔案會直接擋下。
另外 `.github/workflows/no-real-data.yml` 會在每次 push 後於 GitHub 上再做一次掃描，
作為第二層防護（即使本機防護被略過也會被攔截）。

## 幣別與匯率

不使用共用匯率表，每筆帳目／每個情境自己帶「幣別」＋「當下匯率」，記帳當下手動輸入，
避免因為忘記更新共用設定而算錯。表單會記住你這次瀏覽器 session 裡同幣別最後輸入過的匯率，
方便重複輸入，但不會持久化存檔。

## 勞健保試算

不內建政府的投保薪資分級表（會過期、需要持續維護），改成你自己在「⚙ 個人參數設定」填入
投保薪資與費率，公式透明固定（`money.js` 的 `grossToNet`/`netToGross`，互為反函式）。
費率預設值僅為示意，請至勞保局/健保署官網核對最新數字後自行修改。

## 已知限制（誠實列出，非隱藏風險）

- GitHub Pages 網址一定是公開的，安全性依賴「私密倉庫真的只放資料、不放這個工具程式碼」。
- 未按「匯出」就關閉分頁會遺失當次輸入（離開頁面時瀏覽器會跳出警告提醒）。
- 手機瀏覽器可以開啟使用，但匯入/匯出檔案與 git 操作仍建議在電腦上進行。
- 工時反推引擎目前只驗證了「週末班」這條鏈，若原表還有「全週班時數」等更深層欄位，需要你自行核對。

## 反推公式的核對狀態

- 買房／買地自建／旅費／喪葬費四個情境的加總公式已用原表數字交叉核對，`通膨後總額 = 總額 × 通膨倍數`
  （一次性直接相乘，非複利），可直接信任。
- 學貸情境的「學期總結」公式已核對，但「學年總結」跨學期加總方式原表有合併儲存格疑慮，已在
  `shared/config.js` 的 `SCENARIO_STUDENT_LOAN` 註解中標明，可自行滾動修正。
- **FIRE／財務獨立退休試算**：每一步公式都已對照原表數字逐項核對，完全吻合，可直接信任。
- **養老金試算**：原表用了較複雜的複利成長試算，從錯位表格無法完全還原，此處改用透明可核對的標準
  公式（每月生活費 × 12 × 退休後年數），已在算式面板中完整標示計算過程。
- **工時反推計算機**：用「期望收益 910,626」與「學貸還款 155,893」兩組真實數字交叉驗證，
  換算鏈與「上一步無條件進位後才往下除」的精度規則皆已確認吻合原表。

## 開發者測試工具

`_dev-tests/` 資料夾裡有一個手刻的極簡 DOM 模擬器（`minidom.js`）和三份互動測試腳本，
在沒有網路權限安裝 jsdom 的環境下用來驗證 `app.js` 的渲染邏輯不會拋出例外。
這個資料夾只在開發時使用，正式部署到 GitHub Pages 時可以刪除，不影響工具運作。
